# 리포 구조 규약

AWS 오프라인 교육 과정별 실습·이론 정리와, 그 과정에서 파생된 에이전트
작업물을 모아두는 모노레포다.

**성격이 다른 두 축이 있다.**

| 축 | 위치 | 성격 |
|---|---|---|
| 과정 | `NN-<과정명>/`, `labs/` | 학습 기록. 시간순·과정별. 내용이 AWS에 종속돼도 무방 |
| 에이전트 | `agents/` | 작업물. 재사용 가능한 계열. **정의상 벤더 독립** |

두 번째를 첫 번째 안에 넣지 않는다. 벤더 독립이 목표인 산출물이 특정 벤더
과정 폴더에 들어가면 계속 어긋나고, 어댑터가 워크스페이스 루트(`.kiro/`,
`.claude/`, `.codex/`)에 생성되므로 과정 폴더에 담기지도 않는다.

## 디렉토리 구조

```
aws-training/
├── README.md                두 축(과정/에이전트) 목록
├── .github/workflows/        CI. 결정론적 게이트가 실제로 돈다
├── .kiro/steering/           항상 로드되는 규칙 (얇게 유지)
├── .kiro/skills/             필요할 때 로드되는 상세 규칙·절차
├── .kiro/ .claude/ .codex/   생성된 어댑터 (직접 수정 금지)
│
├── agents/                   벤더 독립 에이전트 계열
│   ├── README.md             계열 개요·설계 원칙·이음새 표
│   ├── docs/                 계열 공통 문서
│   ├── core/                 공유 코드 (2번째 에이전트 이후)
│   └── <도메인>/              에이전트 하나당 폴더 하나
│
├── NN-<과정명>/                과정 하나당 폴더 하나 (번호는 학습 순서)
│   ├── README.md             실습 목록 표
│   ├── notes/                이론 정리 (주제 기반 kebab-case .md)
│   └── <실습명>/              실습 하나당 폴더 하나
│
└── labs/                     과정에 속하지 않는 기능 단위 랩
    ├── README.md             랩 목록 표
    └── <랩명>/
```

- 과정 폴더명은 **`NN-kebab-case`** (`01-generative-ai-essentials`). 번호는
  과정을 들은 순서. 알파벳 정렬이 학습 순서와 어긋나 지저분해 보이는 문제를
  막는다. 새 과정을 들으면 기존 마지막 번호 다음을 붙인다(중간에 끼워 넣지
  않는다 — 기존 번호 재배치는 링크가 전부 걸린 리네임이라 비용이 크다).
- `labs/`는 **번호를 붙이지 않는다.** 특정 시점 과정이 아니라 과정에 안
  묶이는 기능 단위 랩의 상시 컨테이너라, 번호를 매기면 매번 새 과정이 추가될
  때 밀려나는 폴더가 된다.
- `labs/`는 특정 과정에 묶이지 않는 기능 단위 실습이다(InvokeModel, Strands
  기초, MCP 트랜스포트 등). 폴더 내부 규칙은 실습과 같다.
- `agents/` 폴더명은 도메인 한 단어로 짧게. 이 경로가 생성되는 모든 어댑터
  설정에 문자열로 박힌다.

## 어떤 작업에 무엇을 읽는가

스티어링은 매 턴 전량 로드되므로 축 중립 규칙만 둔다. 축·도메인에 묶인 상세
규칙은 스킬에 있고 필요할 때만 로드된다.

| 작업 | 참조 |
|---|---|
| 실습·랩 폴더 생성, AWS 리소스 스크립트 | `aws-lab-conventions` 스킬 |
| `agents/` 아래 코드 편집, 새 에이전트 | `agent-conventions` 스킬 |
| 에이전트 커밋·공개 전 검증 | `agent-release-check` 스킬 |
| README 작성·점검, 기술 배지 | `readme-audit` 스킬 |
| Streamlit UI, 색상 대비 | `streamlit-ui` 스킬 |
| 코드 리뷰·리팩토링 판단 | `code-review` 스킬 |
| Strands Agents 설계 | `strands-agents` 스킬 |
| Python / 쉘 / Git / 응답 / AI 표기 | 각 `*-conventions.md`, `response-style.md`, `ai-attribution.md` |

스티어링에 새 규칙을 넣기 전에 **한 축에만 해당하는지** 확인한다. 한 축
전용이면 스티어링이 아니라 스킬로 간다.
