# AI 기여 표기 규칙

이 리포는 AI 코딩 에이전트(Kiro CLI)와 함께 작업한다. 트러블슈팅 섹션에
"~을 확인했습니다"처럼 1인칭으로 쓰면, 실제로 겪고 판단한 사람과 AI가
조사·실행한 내용이 뒤섞여 독자가 구분할 수 없다. 이는 정직성 문제다.

## 원칙

**AI가 실행·조사한 내용을 지우거나 뭉뚱그리지 않는다.** 도구 실행 결과
(에러 메시지, IAM 시뮬레이터 출력, 검증 로그)는 실제로 있었던 근거이므로
그대로 남긴다. 대신 **누가 그 판단을 내렸는지 주어를 정확히 쓴다.**

- "전부 AI가 했다"처럼 뭉뚱그리는 표기는 오히려 덜 정직하다. 어떤 프롬프트로
  뭘 시켰고, 어떤 부분을 사람이 검토·선택했는지가 사라지기 때문이다.
- 반대로 AI가 조사한 사실을 사람이 한 것처럼 1인칭으로 쓰는 것도 정직하지
  않다.

## 표기 방법

### 1. 실습 README 상단에 협업 방식 한 줄 명시

각 실습 README의 "설계 결정과 트러블슈팅" 섹션 시작 부분에 다음과 같이
적는다:

```markdown
## 설계 결정과 트러블슈팅

이 실습은 Kiro CLI(모델: claude-sonnet-4.6 등 실제 사용 모델)와 함께
진행했습니다. 아래 트러블슈팅은 AI 에이전트가 실행한 도구 결과(로그·에러
메시지)를 근거로 정리했으며, 어떤 해결 방향을 택할지는 사람이 검토·승인한
내용입니다.
```

실제 사용한 모델명은 세션 시점 기준으로 정확히 적는다(추측하지 않는다).

### 2. 개별 항목의 주어 구분

- **사람이 직접 판단·선택한 것**: "~하기로 했다", "~을 택했다" (1인칭 유지)
- **AI가 도구로 조사·검증한 사실**: "Kiro가 확인한 결과 ~", "AI 에이전트가
  실행한 IAM 시뮬레이터 결과 ~"처럼 주어를 명시
- **도구 실행 결과 자체(로그, 출력)**: 원문 그대로 인용 (코드 블록), 가공하지
  않음

예시 (Before/After):

```markdown
<!-- Before: 누가 확인했는지 불명확 -->
IAM 정책 시뮬레이터로 원인을 특정했습니다.

<!-- After: 주어 명시 -->
Kiro가 IAM 정책 시뮬레이터를 실행해 원인을 특정했다. 결과를 검토한 뒤
Marketplace 구독이 SCP로 막혀 있다고 판단해 LLM 폴백 방식으로 전환하기로
했다.
```

### 3. 과도한 표기는 피한다

문장마다 "AI가", "제가"를 반복하면 가독성이 떨어진다. 섹션 상단의 협업
방식 한 줄이 전체 맥락을 설명하므로, 개별 문장은 **사람의 판단이 들어간
지점(왜 이 방법을 택했는지, 무엇을 우선했는지)에서만** 주어를 명시하면
충분하다. 단순 사실 확인(도구 출력 재인용)까지 매번 표기하지 않는다.

## 적용 범위

- 새로 작성하는 실습 README부터 적용한다.
- 기존 README를 업데이트하는 시점에 맞춰 점진적으로 반영한다. 기존 문서를
  전부 소급 수정할 필요는 없다.
