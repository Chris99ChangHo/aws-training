# 에이전트 릴리스 점검

## 왜 스킬로 두는가

이 절차는 **매번 같은 순서로, 빠짐없이** 돌아야 의미가 있다. 한 항목만
건너뛰면 통과 보고가 거짓이 된다. 실제로 그런 일이 있었다:
`build.py --check`만 보고 "드리프트 없음"을 확인했는데, 생성된 허용 규칙
하나가 존재하지 않는 경로를 가리켜 영구히 매칭되지 않고 있었다. 드리프트
검사는 *출력이 소스와 일치하는가*만 보고 *출력이 뜻대로 동작하는가*는
보지 않는다.

그래서 이 스킬의 핵심 원칙은 하나다.

**생성기에는 두 종류의 검증이 필요하다 — 안정성(드리프트)과 성질(동작).**
안정성만 검사하면 틀린 출력이 안정적으로 틀린 채 남는다.

## 실행 순서

순서에 의미가 있다. 앞 단계가 뒤 단계의 전제다.

### 1. 어댑터 재생성과 드리프트

```bash
python3 agents/<도메인>/adapters/build.py --check   # exit 1이면 드리프트
python3 agents/<도메인>/adapters/build.py           # 필요 시 재생성
python3 agents/<도메인>/adapters/build.py --check   # 재확인 exit 0
```

폴더를 옮긴 직후라면 **반드시 재생성한다.** 경로가 어댑터에 문자열로
박히기 때문이다.

### 2. 테스트 전량

모든 하네스 테스트를 돌리고 **케이스 수를 세어 기록한다.** "전부 통과"가
아니라 "몇 개가 통과했는가"를 남긴다. 케이스 수가 줄었으면 테스트가
조용히 빠진 것이다.

```bash
sh   agents/<도메인>/tests/test_*.sh
python3 agents/<도메인>/tests/test_*.py
```

### 3. 생성물의 성질 검사

테스트가 아래를 덮고 있는지 확인한다. 없으면 **추가한다.** 이것이 1번이
잡지 못하는 영역이다.

| 검사 | 왜 |
|---|---|
| 허용 규칙이 `^...$`로 앵커링 | 앵커 없는 허용 규칙은 없는 것보다 나쁘다 (`evil && git status`가 매칭됨) |
| 규칙의 리터럴 경로가 디스크에 실존 | 죽은 규칙 탐지. 정규식 리터럴 머리를 뽑아 `is_file()` 확인 |
| 읽기 전용 명령만 자동 승인 | 허용 목록이 변경 명령까지 덮지 않는지 (`git push` 등) |
| 거부 규칙이 실제 문자열을 막는지 | 목록의 존재가 아니라 동작을 검사 |
| 생성물에 홈 디렉토리·절대 경로 없음 | 커밋 파일에 개인 환경이 박히는 것 방지 |
| 생성물이 JSON/TOML로 파싱됨 | 하네스가 로드조차 못 하는 상태 방지 |

새 검사를 추가했으면 **변이 테스트로 실효성을 확인한다.** 소스에 결함을
일부러 넣고 테스트가 실패하는지 본다. 실패하지 않으면 그 테스트는
장식이다. 확인 후 반드시 원복한다.

### 4. 하네스 로드 확인

생성만 되고 로드되지 않는 설정은 통과가 아니다.

```bash
kiro-cli agent validate --path .kiro/agents/<이름>.json
kiro-cli agent list        # Workspace 목록에 보이는지
```

`kiro-cli agent validate`는 에러를 출력하면서 exit 0을 반환한 이력이 있다.
**종료 코드가 아니라 출력 텍스트를 읽는다.**

### 5. README 수치 실측

README에 적힌 숫자를 전부 다시 센다. 줄 수, 테스트 케이스 수, 차단
케이스 수, 비율.

```bash
wc -l agents/<도메인>/**/*.py agents/<도메인>/**/*.sh
```

- 비율(예: "하네스 종속 1.4%")은 분자·분모의 **정의를 README에 적는다.**
  정의 없는 비율은 검증할 수 없다.
- 과거 서술("당시 수치가 틀렸다")에는 **구체적 숫자를 넣지 않는다.**
  실제 값이 바뀔 때마다 그 문장이 다시 어긋난다.

### 6. 민감 정보와 스타일

```bash
grep -rn "/Users/\|$(whoami)" --include="*.py" --include="*.md" agents/
grep -rnE "[0-9]{12}" --include="*.py" --include="*.md" agents/
awk 'length>88 {print FILENAME":"FNR}' $(find agents -name "*.py")
```

테스트 픽스처의 합성 경로(`/Users/x/.aws/credentials` 같은 차단 대상
문자열)는 예외다. 실제 홈 디렉토리와 구분한다.

### 7. 문서 링크

에이전트 README는 길어서 상대 경로 링크가 깨지기 쉽다. 폴더를 옮긴
뒤에는 특히 확인한다. 마크다운 로컬 링크 대상이 실존하는지 전수 검사한다.

## 보고 형식

항목별로 **실측값**을 적는다. "통과"만 쓰지 않는다.

```
어댑터 드리프트  없음 (--check exit 0)
테스트          guard_scope 100/100, gate 34/34, mcp 20/20, adapters 19/19 = 173
하네스 로드      kiro-cli agent list에 Workspace로 표시
README 수치      전 항목 wc -l 실측과 일치
민감정보         없음 (합성 픽스처 6건 제외)
링크            로컬 64개, 깨짐 0
```

검증하지 못한 항목은 **"확인 못함"으로 명시한다.** 예: 스캐너가 설치되지
않아 종단 스캔을 못 돌렸다면 그렇게 적는다. 빠뜨리고 통과로 보고하는 것이
가장 나쁘다.
