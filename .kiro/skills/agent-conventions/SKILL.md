# 벤더 독립 에이전트 규약

`agents/<도메인>/`에 적용된다. 전부 `agents/security/`에서 실제로 겪고 검증한
내용이며, 근거는 각 에이전트 README의 트러블슈팅에 있다.

이 규칙들은 `agents/README.md`에도 설명으로 있다. README는 읽는 사람을 위한
설명이고, 이 스킬은 **코드를 쓸 때 적용되는 제약**이다. 둘이 어긋나면
`agents/README.md`가 아니라 실제 코드를 근거로 판단한다.

## 1. 종속되는 층이 두 개다

| 층 | 없애는 방법 |
|---|---|
| 클라우드 벤더 종속 | 오픈소스 도구 + 개방 표준(SARIF 등) |
| **하네스 종속** | 중립 소스 1벌 → 하네스별 어댑터 **생성** |

두 번째가 더 끈질기다. "Kiro 대신 Claude Code"는 종속 대상만 바꾸는 거래다.
경계를 하네스 **바깥에** 그어야 한다.

적용: 특정 벤더의 API·SDK·모델에 의존하는 코드를 새로 넣지 않는다. 필요하면
어댑터 층으로 밀어내고, 코어는 개방 표준 형식만 다룬다.

## 2. 어댑터는 손으로 쓰지 않고 생성한다

손으로 쓴 설정 파일이 2개가 되는 순간 갈라진다. 중립 소스(프롬프트 +
manifest)에서 생성한다.

- **`.kiro/`, `.claude/`, `.codex/`의 에이전트 설정을 직접 편집하지 않는다.**
  생성물이다. 고칠 것이 있으면 manifest나 프롬프트를 고치고
  `adapters/build.py`로 재생성한다.
- `build.py --check`로 드리프트를 잡는다(exit 1이면 드리프트).
- 폴더를 옮긴 직후에는 **반드시 재생성한다.** 경로가 어댑터에 문자열로
  박히기 때문이다.

**드리프트 검사만으로는 부족하다.** `--check`는 *출력이 소스와 일치하는가*만
보고 *출력이 뜻대로 동작하는가*는 보지 않는다. 실제로 생성된 허용 규칙 하나가
존재하지 않는 경로를 가리켜 영구히 매칭되지 않은 결함이 있었다. 생성물의
성질 검사는 `agent-release-check` 스킬 3절에 있다.

## 3. 종료 코드로 "못 했다"와 "문제 없다"를 구분한다

| 코드 | 뜻 |
|---|---|
| 0 | 실행 완료, 문제 없음 |
| 1 | 실행 완료, **발견 있음** |
| 2 | 거부 (권한 경계 위반) |
| 3 | **도구 미설치** |
| 4 | 실행 실패 |

3번을 0번과 섞으면 도구가 없는 상태가 "깨끗함"으로 보고된다. 실제로 게이트가
빈 리포트를 통과 처리하는 결함이 독립 감사에서 나왔다.

발견(1)은 도구마다 관례가 다르므로 래퍼에서 정규화한다. 래퍼 구현 규칙은
`shell-conventions.md`에 있고, 아래 두 항목은 스캐너 래퍼에만 해당한다.

**실패해도 하류가 읽을 수 있는 산출물을 남긴다.** 산출물을 소비하는 다음
단계가 있으면, 아무것도 못 만든 경우에도 **형식이 유효한 빈 산출물**을 쓴다.
파일이 없는 것과 내용이 없는 것을 하류가 구분하지 못하면 "없음"이 "깨끗함"으로
보고된다. 근거: `write_empty_sarif()` — 스캐너가 결과를 못 냈을 때도 병합·게이트
단계가 well-formed SARIF를 받도록 빈 run을 쓴다.

**`shellcheck source=` 지시 주석을 남긴다.** `.` 로 라이브러리를 읽어들일 때
정적 분석기가 대상을 못 찾으므로 알려준다.

```sh
# shellcheck source=_lib.sh
. "$(dirname "$0")/_lib.sh"
```

## 4. 강제 지점은 진입 경로 수만큼, 규칙은 항상 하나

MCP 도구 호출은 쉘 명령이 아니라서 **PreToolUse 훅이 보지 못한다.** 통제를
훅에만 두면 에이전트가 MCP를 쓰는 순간 사라진다.

- 진입 경로(쉘 훅, MCP 서버, 파일 읽기 도구)마다 강제 지점을 둔다.
- 규칙 자체는 **한 파일에** 둔다(`security/scanners/_scope_lib.sh`). 규칙을
  복제하면 한쪽만 고쳐진다.
- 새 진입 경로를 추가할 때는 그 경로가 기존 강제를 우회하지 않는지 먼저
  확인한다. 3번째 하네스(Codex)를 붙였을 때 파일 읽기 도구가 훅을 우회하고
  있던 것이 이 방식으로 드러났다.

## 5. 판정을 LLM에 맡기지 않는다

빌드를 막을지 말지는 파일에서 숫자를 읽어 결정한다. 같은 입력에 같은 답이
나오고, 감사 가능하고, 구독이 없어도 동작한다.

LLM이 하는 일과 결정론적 코드가 하는 일의 경계를 코드 구조로 표현한다 —
게이트·스코프 검증은 스크립트, 서술·독해는 프롬프트.

## 6. 소비자가 2개 이상일 때만 추상화한다

`security/`에서 하네스가 2개일 때는 추상화가 잘 된 줄 알았다. 3번째를 붙이자
보안 구멍이 드러났다. 2개로는 "원래 이런 건가"와 "내가 놓친 건가"를 구분할
수 없다.

- `agents/core/`는 **두 번째 에이전트가 실제로 생긴 뒤에** 추출한다. 그때까지
  후보는 `agents/README.md`의 이음새 표에만 기록한다.

  실측 근거: 두 번째 에이전트를 만들며 게이트를 `agents/core/`로 추출해 봤다.
  옮기는 순간 결함이 드러났다 — 게이트가 `__file__` 기준으로 리포트 디렉토리와
  manifest를 찾고 있어서 공유 위치에서 깨졌다. **공유 도구는 자기 위치에서
  어느 소비자를 위해 도는지 알 수 없다.** 그 에이전트를 폐기하자 소비자가
  하나로 돌아갔고, 공유 때문에 넣은 우회로만 남아서 추출도 되돌렸다.
- "범용"을 판단할 때 **도메인 축과 하네스 축을 혼동하지 않는다.**
  `adapters/build.py`는 도메인 축에서 완전 범용이지만 하네스 축에서는 317줄이
  종속이다. 두 축은 직교한다.

## 7. 폴더와 경로

- 폴더명은 **도메인 한 단어**로 짧게 짓는다(`security`, `devops`). 이 경로가
  생성되는 모든 어댑터 설정에 문자열로 박히므로 길면 손해다. 폴더명과
  에이전트 이름(`generic-sec-agent`)은 별개다.
- 경로를 코드에 절대 경로로 쓰지 않는다. 파일 위치에서 계산한다
  (`LAB_ROOT.relative_to(WORKSPACE_ROOT)`). 폴더를 옮겨도 재생성만 하면
  어댑터가 자동으로 맞고, 홈 디렉토리·사용자명이 커밋되지 않는다.
- 계열 공통 설계 원칙은 `agents/README.md`에 모으고, 개별 에이전트 README는
  자기 트러블슈팅만 담는다.

## 8. 검증되지 않은 것을 감춘다

- 만든 사람이 아닌 검토자에게 감사받는다. `security/`는 테스트 91개가 전부
  통과한 상태에서 독립 감사를 받았고 **결함 8개(Critical 2)** 가 나왔다.
- 각 에이전트 README에 **"검증하지 못한 것"** 표를 유지한다. "됐다"만 적힌
  문서는 근거가 없다.
- 새 테스트를 추가했으면 **변이 테스트로 실효성을 확인한다.** 소스에 결함을
  일부러 넣고 테스트가 실패하는지 본다. 실패하지 않으면 그 테스트는
  장식이다.

## 관련

- 커밋·공개 전 회귀 검증 절차 → `agent-release-check` 스킬
- 쉘 래퍼 작성 규칙 → `shell-conventions.md`
- README 항목·배지 → `readme-audit` 스킬
