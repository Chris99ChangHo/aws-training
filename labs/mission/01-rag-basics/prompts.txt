시리즈 1: RAG 기초
시리즈 개요
다이닝 컨시어지 서비스 "강남 다이닝"의 강남 식당 8곳 데이터를 Knowledge Base로 구축하고, 메타데이터 필터링으로 검색 정밀도를 높인 뒤, Streamlit 채팅 앱으로 완성합니다. 여기서 만든 식당 KB는 「RAG 심화」·「AgentCore 통합」·「에이전트 평가」가 재사용하는 출발점입니다.

KB 구축 — 강남 식당 컨시어지
초급
제공된 강남 식당 데이터로 Amazon Bedrock Knowledge Base를 생성하고 시맨틱 검색을 확인합니다.

미션 브리핑
다이닝 컨시어지 서비스 "강남 다이닝"에서 AI 식당 컨시어지를 만들려고 합니다. 강남 일대 식당 8곳의 기본 정보·메뉴·리뷰가 담긴 데이터를 제공합니다.

이 미션에서는:

제공된 식당 데이터를 S3 버킷에 업로드하고
Knowledge Base를 생성해 데이터 소스를 동기화한 뒤
시맨틱 검색이 동작하는지 API와 미니 검색창에서 확인합니다

목표
식당 데이터 17개 객체를 S3 dining-kb-data-<YOUR_ACCOUNT_ID>에 업로드
dining-concierge-kb 생성(Available) + 데이터 소스 동기화 완료
RetrieveAndGenerate 응답에 트라토리아 벨라·르 비스트로 포함
브라우저 미니 검색창에서 KB 근거 답변 확인
제약 조건
임베딩 모델: Amazon Titan Text Embeddings V2
제공된 데이터 파일을 그대로 사용
리전: us-west-2
UI: Streamlit 미니 검색창(KB 검색·답변)

KB 고급 검색 — 메타데이터 필터, 하이브리드, 리랭킹
중급
Knowledge Base의 메타데이터 필터링, 하이브리드 서치, 리랭킹을 활용하여 검색 품질을 극대화합니다.

미션 브리핑
선행 미션에서 구축한 식당 KB의 검색 정확도를 높여야 합니다. 현재는 "한식당만 알려 주세요"라고 해도 다른 카테고리 식당이 섞여 나옵니다. KB가 제공하는 3가지 고급 검색 기법을 모두 적용하여 품질을 개선하세요.

메타데이터 필터링: category·location 등 메타데이터로 원하는 조건의 식당만 정확히 반환
하이브리드 서치: 시맨틱 검색 + 키워드 검색을 결합하여 식당명 같은 고유명사 매칭 향상
리랭킹: 검색 결과를 모델이 재정렬하여 관련성 순위 개선
각 기법을 적용하고 적용 전/후 결과를 비교한 뒤, 필터가 적용된 검색을 미니 검색창에서 눈으로 확인하세요.

선행 조건
선행 미션에서 만든 dining-concierge-kb (KB ID 필요, .metadata.json 포함 동기화 완료)

목표
메타데이터 필터 검색으로 카테고리별 결과 확인 (필터 전/후 대비)
하이브리드 서치(시맨틱+키워드)를 설정하고 식당명 키워드 매칭 결과 확인
리랭킹 모델을 적용하여 상위 결과의 관련성 개선 확인
3가지 기법 적용 전/후 검색 품질 비교 (같은 질문으로 결과 대비)
검색 UI 확인 — Streamlit 미니 검색창에서 같은 질문에 필터 조건을 바꿔 결과가 달라지는 것을 브라우저에서 확인
제약 조건
선행 미션에서 만든 KB를 그대로 사용
메타데이터 키: category, location, price_min/price_max, max_party_size 등 (실습 데이터의 .metadata.json 기준)
비교 기준: 동일 질문 "회식하기 좋은 한식당 추천해 주세요"로 각 설정별 결과 비교
리전: us-west-2
UI: Streamlit 미니 검색창(필터 조건 전환 비교)

Streamlit RAG 챗봇
중급
Knowledge Base와 메타데이터 필터를 활용한 대화형 식당 추천 챗봇을 Streamlit으로 구현합니다.

미션 브리핑
선행 미션들에서 구축한 KB(dining-concierge-kb)와 메타데이터 필터를 활용하여 "강남 다이닝" 고객이 직접 대화할 수 있는 식당 추천 챗봇 UI를 만들어야 합니다.

이 미션에서는:

Streamlit으로 채팅 인터페이스를 구성하고
사이드바에서 선택한 카테고리만 검색하는 필터를 붙인 뒤
채팅 히스토리가 유지되는 멀티턴 대화와 근거 카드 표시를 완성합니다
선행 조건
선행 미션에서 만든 dining-concierge-kb (KB ID 필요, .metadata.json 포함 동기화 완료)

목표
streamlit run app.py로 앱이 정상 실행됨
사이드바 카테고리 드롭다운에서 선택한 카테고리로 필터 검색 동작
채팅 멀티턴 유지 (이전 대화가 화면에 남아있음)
식당 추천 결과가 카드 UI로 표시됨
제약 조건
streamlit run app.py로 실행
사이드바에 카테고리 드롭다운(전체, 한식, 일식, 중식, 이탈리안, 프렌치, 채식/비건) 포함
이전 대화 히스토리 유지 (session_state 활용)
리전: us-west-2

도전 과제 방향
예산 계산기: 사이드바에 인원수 입력(st.number_input)을 두고 질문 텍스트에 인원수를 덧붙이면 KB의 가격 정보를 근거로 예상 비용을 답하게 할 수 있습니다 — 답변과 분리된 계산 표시가 필요하면 citations의 근거 문서에서 가격대를 뽑아 인원수와 곱해 보여 줍니다.
지도 연동(folium): folium·streamlit-folium을 설치하고 식당명 → 가까운 역 좌표 딕셔너리를 만들어, 추천에 등장한 식당만 마커로 얹습니다 — 추천 식당 판별은 답변 텍스트 파싱보다 citations → retrievedReferences의 파일명이 안전합니다.
식당 비교 뷰: st.columns(2)나 표로 두 식당의 가격대·평점·최대 수용 인원을 나란히 배치합니다 — 값은 근거 문서에서 뽑고, 리렌더링에 사라지지 않도록 st.session_state에 담아 둡니다.
핵심 포인트
st.chat_input + st.session_state.messages로 멀티턴 채팅 히스토리를 유지합니다
화면 히스토리는 표시용 — 대화 맥락은 retrieve_and_generate의 sessionId로 이어집니다
사이드바 st.selectbox로 메타데이터 필터를 UI로 제어합니다
@st.cache_resource로 boto3 클라이언트를 캐싱하여 매 요청마다 재생성하지 않습니다
KB 응답의 citations → retrievedReferences에서 근거 문서를 추출하여 카드로 표시합니다
