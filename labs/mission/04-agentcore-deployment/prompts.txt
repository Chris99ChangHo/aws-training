시리즈 4: AgentCore 배포
시리즈 개요
로컬에서만 돌던 다이닝 컨시어지를 AgentCore에 올립니다. 배포 방식은 2가지 — 코드 0줄, 모델과 시스템 프롬프트의 선언 스펙만으로 만드는 Managed Harness와, 에이전트 코드를 그대로 올리고 엔드포인트를 관리하는 Runtime입니다. 두 방식을 차례로 경험한 뒤, 마지막에는 배포 구조를 한 단계 올립니다 — 프로덕션 트래픽을 안정 버전에 고정하고, 새 버전은 카나리 엔드포인트로만 검증한 뒤 승격하며, 문제가 보이면 버전 포인터만 되돌리는 카나리 배포와 롤백입니다.

여기서 배포한 Runtime은 「AgentCore 통합」과 「다이닝 웹 서비스」의 선행 산출물입니다

AgentCore CLI로 다이닝 에이전트를 Runtime에 배포하고 호출을 검증합니다.

미션 브리핑
선행 미션에서 만든 다이닝 에이전트를 AgentCore Runtime에 배포합니다. 지금까지 로컬에서만 돌던 에이전트가 관리형 엔드포인트를 가진 프로덕션 에이전트가 됩니다. 선언형(Harness) 배포는 별도 미션에서 다룹니다.

이 미션에서는:

AgentCore CLI로 에이전트 프로젝트를 만들고 식당 도구를 통합한 뒤
Runtime에 배포해 콘솔에서 배포 상태를 확인하고
CLI·코드·미니 Streamlit 앱 세 경로로 호출을 검증합니다
선행 조건
선행 미션에서 만든 식당 도구 tools.py (search_restaurants·get_menu)

DiningConcierge 에이전트 프로젝트를 만들고 식당 도구를 통합해 주세요.
- agentcore create --name DiningConcierge --framework Strands --model-provider Bedrock --memory none
- app/DiningConcierge/main.py에 식당 검색·메뉴 도구(search_restaurants, get_menu) 통합
- check_reservations는 로컬 MCP 서버 의존이라 배포 범위에서 제외

확인
프로젝트에 agentcore/ 설정과 app/DiningConcierge/main.py 존재
main.py에 식당 도구와 @app.entrypoint 포함되어

에이전트를 AgentCore Runtime에 배포해 주세요.
- agentcore deploy -y
- 출력의 Runtime ARN 기록
- 콘솔 Build > Runtime에서 상태 확인

확인
agentcore deploy 성공 메시지 출력
콘솔 > Build > Runtime에서 DiningConcierge 상태 Ready

배포된 에이전트를 두 방식으로 호출해 검증해 주세요.
- CLI: agentcore invoke "강남 식당 추천해 주세요"
- test_invoke.py — boto3 bedrock-agentcore의 invoke_agent_runtime으로 같은 Runtime 호출

확인
agentcore invoke 응답에 식당 추천 포함
test_invoke.py 실행 시 같은 Runtime의 응답 수신

배포된 Runtime을 호출하는 미니 Streamlit 앱으로 확인해 주세요.
- app.py — 「Harness 선언 배포」 미션의 앱이 있으면 호출부만 이 미션의 Runtime(invoke_agent_runtime)으로 교체해 재사용, 없으면 test_invoke.py의 호출을 함수로 빼서 새로 작성
- streamlit run app.py
- 브라우저에서 "강남 식당 추천해 주세요" 입력

도전 과제 방향
스트리밍 호출: agentcore invoke --stream으로 응답을 도착하는 대로 받을 수 있습니다. 엔트리포인트가 async 스트리밍이면 boto3 응답 본문에 SSE 프레이밍(data: 줄)이 섞일 수 있습니다.
도구 교체 후 재배포: 코드 수정 후 agentcore deploy만 재실행합니다 — 단계별 가이드는 AgentCore CLI 배포 실습의 심화 과제에서 다룹니다.
버전 카나리: 재배포마다 새 버전이 생기며, 버전 고정 엔드포인트로 점진 검증할 수 있습니다 — 후속 미션에서 다룹니다.
Gateway 도구 연결: 배포된 에이전트에 Knowledge Base를 도구로 붙이는 결선은 후속 미션에서 다룹니다.
핵심 포인트
프레임워크 에이전트 프로젝트는 agentcore create에 --framework·--model-provider·--memory 3개를 모두 지정해 비대화식으로 생성합니다 — --defaults는 Harness 프로젝트를 만드는 플래그이므로 이 미션에서는 쓰지 않습니다
agentcore deploy는 코드 패키징부터 Runtime 생성, 엔드포인트 활성화까지 자동 처리합니다
도구를 바꾼 뒤에는 agentcore deploy만 다시 실행하면 즉시 반영됩니다
프로덕션 애플리케이션은 CLI가 아니라 boto3 bedrock-agentcore 데이터 플레인의 invoke_agent_runtime으로 호출합니다 — 응답은 response 블롭에 담겨 옵니다
