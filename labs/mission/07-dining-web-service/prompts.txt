시리즈 7: 다이닝 웹 서비스
시리즈 개요
지금까지 다이닝 에이전트는 AWS 자격 증명이 있어야만 호출할 수 있었습니다. 이 시리즈에서는 그 에이전트를 누구나 브라우저로 쓰는 웹 서비스로 만듭니다. SAM으로 서버리스 API를 세우고, AWS 공식 디자인 시스템 Cloudscape의 생성형 AI 채팅 컴포넌트로 프론트엔드를 만들고, S3+CloudFront로 공개한 뒤, 마지막에는 에이전트·API·프론트 3계층을 한 모노레포에 담아 git push 한 번으로 전부 배포되는 풀스택 파이프라인으로 완성합니다.

"""dining-web API — GET /는 임시 HTML 페이지, POST /ask는 AgentCore Runtime 프록시."""
import json
import os

import boto3

agent_core = boto3.client("bedrock-agentcore")
AGENT_RUNTIME_ARN = os.environ["AGENT_RUNTIME_ARN"]

HTML = """<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="utf-8">
  <title>강남 다이닝 API</title>
  <style>
    body { font-family: sans-serif; max-width: 640px; margin: 80px auto; color: #232f3e; }
    #answer { margin-top: 16px; white-space: pre-wrap; }
  </style>
</head>
<body>
  <h1>강남 다이닝</h1>
  <input id="q" type="text" style="width:80%" placeholder="식당을 물어보세요">
  <button onclick="ask()">전송</button>
  

<div id="answer"></div>

  <script>
    async function ask() {
      const prompt = document.getElementById('q').value;
      document.getElementById('answer').textContent = '답변 생성 중...';
      const res = await fetch('/ask', {
        method: 'POST',
        headers: {'Content-Type': 'application/json'},
        body: JSON.stringify({prompt})
      });
      const data = await res.json();
      document.getElementById('answer').textContent = data.answer;
    }
  </script>
</body>
</html>"""

def _extract_answer(response) -> str:
    """invoke_agent_runtime 응답 본문에서 텍스트를 추출합니다."""
    raw = response["response"].read().decode("utf-8")
    if "text/event-stream" in response.get("contentType", ""):
        chunks = []
        for line in raw.splitlines():
            if line.startswith("data:"):
                chunk = line[len("data:"):].strip()
                try:
                    chunk = json.loads(chunk)
                except json.JSONDecodeError:
                    pass
                if isinstance(chunk, str):
                    chunks.append(chunk)
        return "".join(chunks)
    try:
        parsed = json.loads(raw)
        return parsed if isinstance(parsed, str) else raw
    except json.JSONDecodeError:
        return raw

def lambda_handler(event, context):
    route = event.get("routeKey", "")

    if route == "GET /":
        return {
            "statusCode": 200,
            "headers": {"Content-Type": "text/html; charset=utf-8"},
            "body": HTML,
        }

    if route == "POST /ask":
        body = json.loads(event.get("body") or "{}")
        prompt = body.get("prompt", "").strip()
        if not prompt:
            return {
                "statusCode": 400,
                "headers": {"Content-Type": "application/json"},
                "body": json.dumps({"error": "prompt가 비어 있습니다."}, ensure_ascii=False),
            }
        response = agent_core.invoke_agent_runtime(
            agentRuntimeArn=AGENT_RUNTIME_ARN,
            qualifier="DEFAULT",
            payload=json.dumps({"prompt": prompt}),
        )
        return {
            "statusCode": 200,
            "headers": {"Content-Type": "application/json"},
            "body": json.dumps({"answer": _extract_answer(response)}, ensure_ascii=False),
        }

    return {
        "statusCode": 404,
        "headers": {"Content-Type": "application/json"},
        "body": json.dumps({"error": f"지원하지 않는 경로입니다: {route}"}, ensure_ascii=False),
    }

도전 과제 방향
저장 즉시 반영: sam sync --watch는 코드 저장 시 Lambda 코드를 직접 업데이트합니다 — sam build && sam deploy 없이 개발 루프를 단축합니다.
대화 이어가기: /ask 요청에 sessionId 필드를 추가하고 Lambda에서 invoke_agent_runtime의 runtimeSessionId로 전달하면 이전 턴을 기억합니다 (33자 이상 필요).
정리 리허설: sam delete는 스택과 배포 아티팩트를 함께 삭제합니다 — samconfig.toml만 남아 있으면 sam build && sam deploy로 동일 스택을 재구축할 수 있습니다.
핵심 포인트
브라우저는 SigV4가 필요한 invoke_agent_runtime을 직접 호출할 수 없습니다 — Lambda 프록시(HTTP API + Lambda)가 웹과 Runtime 사이의 경계입니다.
HTTP API payload 2.0에서 statusCode 없는 반환값은 통째로 JSON 본문으로 추론됩니다 — HTML은 statusCode·headers·body를 갖춘 dict가 필수입니다.
InvokeAgentRuntime의 IAM Resource는 런타임 ARN과 !Sub "${AgentRuntimeArn}/*" 둘 다 필요합니다 — 런타임만 넣으면 AccessDenied입니다.
Lambda 내장 boto3에 기대지 않습니다 — requirements.txt에 boto3를 명시해야 bedrock-agentcore 클라이언트가 보장됩니다.
HTTP API를 명시적 리소스로 선언한 이유는 확장 자리 때문입니다 — 암묵 생성 API로는 후속 미션에서 CORS 속성을 붙일 자리가 없습니다.

// src/App.jsx — 채팅 UI
import { useState } from 'react';
import Container from '@cloudscape-design/components/container';
import Header from '@cloudscape-design/components/header';
import SpaceBetween from '@cloudscape-design/components/space-between';
import PromptInput from '@cloudscape-design/components/prompt-input';
import ChatBubble from '@cloudscape-design/chat-components/chat-bubble';
import Avatar from '@cloudscape-design/chat-components/avatar';

const API_URL = import.meta.env.VITE_API_URL;

export default function App() {
  const [messages, setMessages] = useState([]);
  const [value, setValue] = useState('');
  const [loading, setLoading] = useState(false);

  const send = async () => {
    const prompt = value.trim();
    if (!prompt || loading) return;
    setValue('');
    setMessages((prev) => [...prev, { role: 'user', text: prompt }]);
    setLoading(true);
    try {
      const res = await fetch(`${API_URL}/ask`, {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ prompt }),
      });
      const data = await res.json();
      setMessages((prev) => [...prev, { role: 'ai', text: data.answer }]);
    } catch (err) {

도전 과제 방향
SPA 라우팅 대비: CloudFront 배포의 커스텀 오류 응답에 403과 404를 응답 페이지 /index.html + HTTP 200으로 매핑합니다 — 비공개 S3 오리진은 없는 경로에 404 대신 403을 돌려주는 경우가 많아 둘 다 매핑하는 것이 안전합니다.
압축·캐시 정책 확인: 배포 동작(Behavior)에서 캐시 정책 CachingOptimized와 압축 설정을 확인하고, 브라우저 개발자 도구 Network 탭에서 응답 헤더의 content-encoding(br·gzip)으로 실제 적용을 확인합니다.
배포 스크립트: 단계 4의 갱신 루프 세 명령(npm run build → aws s3 sync dist/ … --delete → aws cloudfront create-invalidation)을 deploy-web.sh 하나로 묶습니다 — 무효화가 끝나기 전의 새로고침은 옛 파일이 보이는 게 정상이므로, 스크립트가 무효화 ID를 출력하게 해 두면 반영 확인이 쉽습니다.
핵심 포인트
공개 호스팅이지만 버킷은 끝까지 비공개입니다 — OAC가 CloudFront의 오리진 요청에 서명하고, 버킷 정책의 AWS:SourceArn Condition이 지정한 배포만 허용합니다
콘솔 생성 위저드에서 "Use recommended origin settings"가 OAC를 자동 구성하고 버킷 정책까지 자동 갱신합니다 — OAI는 legacy 방식이라 신규 구성에 쓰지 않습니다
Default root object는 루트(/) 요청에만 적용됩니다 — SPA 라우팅이 있으면 커스텀 오류 응답이 필요합니다

도전 과제 방향
평가 게이트 이식: Deploy 앞에 Test 스테이지 추가 → Strands Evals buildspec을 별도 CodeBuild 프로젝트로 만들어 Test 스테이지에 배치. 평가 통과 판정은 빌드 종료 코드 0/1로 제어
프론트 전용 빠른 경로: 아티팩트에는 .git이 없으므로 git diff로는 판정할 수 없습니다 — buildspec 첫머리에서 아티팩트 내 해당 계층 파일들의 체크섬을 계산해 S3에 보관한 지난 값과 비교하고, 같으면 exit 0으로 조기 성공. agentcore deploy는 2~3분이므로 프론트 단독 커밋 체감이 확연히 달라집니다
수동 승인: Deploy 스테이지 앞에 Manual approval 액션 추가 → SNS 토픽 연결해 이메일 알림 → 승인 링크 클릭 후 배포 진행
핵심 포인트
콘솔에서 만든 CodeCommit 소스 파이프라인은 EventBridge 규칙이 자동 생성됩니다 — push가 곧 트리거이고, Release change는 리허설용입니다
순차성의 실체는 RunOrder입니다 — 같은 스테이지의 3액션에 1·2·3을 주면 에이전트 배포가 실패했을 때 API·프론트 배포가 실행되지 않습니다
이미지 aws/codebuild/amazonlinux-x86_64-standard:5.0에는 sam CLI·Node가 사전 설치되어 있지만, agentcore CLI(npm install -g @aws/agentcore)와 uv(pip install uv)는 install 단계에서 설치하고, python 버전은 runtime-versions로 고정합니다
콘솔 위저드의 Deploy 스테이지 공급자 목록에는 CodeBuild가 없습니다 — 위저드로는 Build 스테이지까지 만들고, 생성 후 편집으로 Deploy 스테이지에 3액션을 배치하는 것이 정본 절차입니다
sam deploy의 두 옵션은 파이프라인 전용입니다 — --no-confirm-changeset(사람이 확인을 눌러줄 수 없음)·--no-fail-on-empty-changeset(API 변경이 없는 커밋에서도 실패하지 않음)
커밋이 곧 배포 단위가 됐습니다 — 에이전트·API·프론트가 한 git 히스토리에 있으니 문제가 생기면 git revert 한 번으로 풀스택 전체가 이전 상태로 돌아갑니다
