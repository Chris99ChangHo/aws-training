# Agents — 벤더 독립 에이전트 계열

AWS가 만들어 제공하는 에이전트를 해체해서, **특정 클라우드 벤더에도 특정 AI
도구(하네스)에도 종속되지 않게** 재구현한 작업물이다.

이 폴더는 상위의 과정 폴더들과 성격이 다르다.

| 축 | 내용 | 성격 |
|---|---|---|
| 과정 폴더 (`generative-ai-essentials/` 등) | AWS 오프라인 수업 이론·실습 | **학습 기록** — 시간순, 과정별 |
| **`agents/`** | AWS 에이전트 해체·재구현 | **작업물** — 재사용 가능한 계열 |

## 에이전트 목록

|---|---|---|---|
| [`security/`](./security) | AWS Security Agent | 동작 (테스트 173) | STRIDE 위협 모델링, SAST/SCA/DAST, SARIF 결정론적 게이트 |

## 폐기한 시도 — DevOps 에이전트

두 번째 에이전트로 DevOps를 만들다가 **폐기했다.** 기록으로 남기는 이유는
판단 근거가 다음 결정에 쓰이기 때문이다.

**1. 첫 계층이 security의 사본이었다.** IaC 스캔을 devops의 일로 보고
`trivy config`를 호출했는데, 같은 픽스처에서 security의 `run_sca.sh`와 rule
ID 13개가 전부 겹쳤다(security 전용 0건, devops 전용 0건). security가 이미
`trivy fs --scanners vuln,secret,misconfig`를 돌고 있었기 때문이다. 파일
종류(`.tf`, `.yaml`)로 소유권을 나눈 것이 원인이었다 — **파일은 경계가 아니다.**

**2. 겹치지 않는 검사만 남기니 범위가 작아졌다.** Trivy 출력을 실측해 이미
보고되는 항목(리소스 limits `KSV-0011/15/16/18`, 이미지 태그 `KSV-0013`,
Dockerfile `HEALTHCHECK` `DS-0026`, 모든 `securityContext`)을 빼고 나면
운영 준비도 8개(state 락, 버전 고정, probe, replica, 롤백 경로, 파이프라인
재현성)가 남았다. 동작하고 테스트도 통과했지만, 원본과의 격차에 비해 결과물이
얇았다.

**3. AWS 원본과 성격이 달랐다.** AWS DevOps Agent는 5개 축 21개 기능이고 본질이
**라이브 프로덕션 텔레메트리 기반 SRE**다 — PagerDuty·ServiceNow에서 조사 착수,
텔레메트리+코드+배포 상관 root cause 분석, 과거 인시던트에서 학습.
CloudWatch·Datadog·Splunk 연동이 전제다. 내가 만든 것은 리포 파일 정적 검사이고
21개 중 1개를 부분 구현한 수준이었다. security는 원본이 리포 코드를 보는 일이
많아 재현 가능했지만, DevOps는 관측성 스택 없이는 성립하지 않는다.

→ 결론: 얇은 두 번째 에이전트보다 **security 하나의 완성도**가 낫다고 판단해
`agents/devops/`를 삭제했다. 히스토리에는 남아 있다(`b51f1ef` 이전).

부수 효과로 `agents/core/gate/` 추출도 되돌렸다. 소비자가 하나로 돌아가면
원칙 3에 어긋나고, 공유 때문에 넣은 `AGENT_ROOT` 우회로(cwd 폴백)가 조용히
틀릴 수 있는 함정으로만 남는다.

## 계열 공통 설계 원칙

에이전트를 하나 더 만들 때 지킬 것들이다. 전부 `security/`에서 실제로 겪고
검증한 내용이다. 근거는 각 에이전트의 README 트러블슈팅에 있다.

### 1. 종속되는 층이 두 개다

| 층 | 없애는 방법 |
|---|---|
| 클라우드 벤더 종속 | 오픈소스 도구 + 개방 표준(SARIF 등) |
| **하네스 종속** | 중립 소스 1벌 → 하네스별 어댑터 **생성** |

두 번째가 더 끈질기다. "Kiro 대신 Claude Code"는 종속 대상만 바꾸는 거래다.
경계를 하네스 **바깥에** 그어야 한다.

### 2. 어댑터는 손으로 쓰지 않고 생성한다

손으로 쓴 설정 파일이 2개가 되는 순간 갈라진다. 중립 소스(프롬프트 +
manifest)에서 생성하고, `--check`로 CI에서 드리프트를 잡는다.

### 3. 소비자가 2개 이상일 때만 추상화한다

`security/`에서 하네스가 2개일 때는 추상화가 잘 된 줄 알았다. **3번째(Codex)를
붙이자 보안 구멍이 드러났다** — 파일 읽기 도구가 훅을 우회하고 있었다.
2개로는 "원래 이런 건가"와 "내가 놓친 건가"를 구분할 수 없다.

같은 이유로 이 폴더의 `core/`도 **두 번째 에이전트가 실제로 생긴 뒤에**
추출한다. 아래 §이음새 참고.

### 4. 강제 지점은 진입 경로 수만큼, 규칙은 항상 하나

MCP 도구 호출은 쉘 명령이 아니라서 PreToolUse 훅이 보지 못한다. 통제를 훅에만
두면 에이전트가 MCP를 쓰는 순간 사라진다. 두 곳에서 강제하되 규칙은 한 파일에
둔다(`security/scanners/_scope_lib.sh`).

### 5. 판정을 LLM에 맡기지 않는다

빌드를 막을지 말지는 파일에서 숫자를 읽어 결정한다. 같은 입력에 같은 답이
나오고, 감사 가능하고, 구독이 없어도 동작한다.

### 6. 종료 코드로 "못 했다"와 "문제 없다"를 구분한다

| 코드 | 뜻 |
|---|---|
| 0 | 실행 완료, 문제 없음 |
| 1 | 실행 완료, **발견 있음** |
| 2 | 거부 (권한 경계 위반) |
| 3 | **도구 미설치** |
| 4 | 실행 실패 |

3번을 0번과 섞으면 도구가 없는 상태가 "깨끗함"으로 보고된다. 실제로 게이트가
빈 리포트를 통과 처리하는 결함이 독립 감사에서 나왔다.

### 7. 만든 사람이 아닌 검토자에게 감사받는다

`security/`는 테스트 91개가 전부 통과한 상태에서 독립 감사를 받았고 **결함
8개(Critical 2)** 가 나왔다. 자기 검증으로는 안 보인다.

### 8. 검증 못 한 것을 문서에 남긴다

"됐다"만 적힌 문서는 근거가 없다. 각 에이전트 README에 "검증하지 못한 것"
표를 유지한다.

## 이음새 — Phase 2에서 `core/`로 올릴 후보

`security/`를 실측 분류한 결과다. DevOps 에이전트를 만들 때 **폴더를 복사하면
약 80%가 중복된다.** 그래서 그 시점에 추출한다. 지금 미리 하지 않는 이유는
위 원칙 3이다.

| 분류 | 줄 수 | 비중 | 해당 파일 |
|---|---|---|---|
| **완전 범용** | 747 | 33% | `adapters/build.py`, `scanners/_lib.sh`, `scanners/preflight.sh` |
| **범용 골격 + 특화 내용** | 1,028 | 46% | `mcp/server.py`, `gate/gate.py`, `gate/merge_sarif.py` |
| **보안 특화** | 472 | 21% | `agent/SYSTEM_PROMPT.md`, `scanners/_scope_lib.sh`, `scanners/run_{sast,sca,dast}.sh` |

여기서 "범용"은 **도메인 축**이다 — DevOps 에이전트가 그대로 쓸 수 있는가.
하네스 축과 혼동하면 안 된다. `adapters/build.py`는 도메인 축에서는 완전
범용이지만(어떤 에이전트든 어댑터가 필요하다) 하네스 축에서는 317줄이
종속이다. 두 축이 직교한다.

`scanners/guard_scope.sh`(417줄)는 내부가 갈린다.

| 구간 | 줄 수 | 성격 |
|---|---|---|
| §1–3 페이로드 파싱 · 구조/카테고리 차단 · 자격증명 | 291 | **범용** — `rm -rf`는 보안 문제가 아니라 그냥 위험한 명령 |
| §4 DAST 타겟 스코프 검증 | 126 | 보안 특화 |

### Phase 2 착수 조건

두 번째 에이전트를 실제로 만들어 본 결과, 아래가 선행 조건으로 확인됐다.
DevOps 시도는 폐기했지만 이 제약은 다음 시도에도 그대로 적용된다.

- `adapters/build.py`는 출력 파일명이 하드코딩되어 있다. 공유하려면 manifest의
  에이전트 이름에서 파생시켜야 한다. **더 큰 제약이 실측으로 드러났다** —
  `.claude/settings.json`과 `.codex/config.toml`은 **프로젝트 단위** 파일이라
  에이전트별로 생성하면 서로 덮어쓴다. 생성기가 에이전트 단위 출력과 프로젝트
  단위 출력을 갈라야 한다. Codex는 프로파일(`~/.codex/<name>.config.toml` +
  `--profile`)로 분리 가능함을 확인했고, Claude Code는 서브에이전트
  frontmatter가 에이전트 단위라 가능하다.
- `scanners/_lib.sh`를 공유하려면 `SEC_REPORT_DIR`을 중립 이름으로 개명해야
  한다. 그 변수는 5개 파일 8곳에 있다.
- `gate/`를 공유하려면 **게이트가 어느 에이전트를 위해 도는지 밖에서 받아야
  한다.** 실제로 옮겨 보니 `__file__` 기준으로 리포트 디렉토리와 manifest를
  찾고 있어서 공유 위치에서 깨졌다. 더 나쁜 것은 테스트가 이를 잡지 못했다는
  점이다 — 폴백값(`high`/0)이 manifest 선언값과 같아 manifest를 한 번도 읽지
  않고 통과했다.
- `mcp/server.py`는 골격과 도구 정의를 분리해야 공유할 수 있다.
